# Zoom-пайплайн — дизайн

Дата: 2026-09-15. Статус: принят Димасом (брейншторм в сессии).

Автоматический контур вокруг записей занятий: обнаружить новую облачную
запись Zoom → забрать → сохранить на NAS → транскрибировать → разобрать
против плана занятия → подготовить черновики (постмортем, рекомендации,
сообщение в MAX со ссылкой на запись). Курс машина не правит — только
черновики для Димаса.

## Решения

1. **Источник — Zoom Cloud** (платный план). Забор через Server-to-Server
   OAuth + Cloud Recording API. Локальные записи и Ecamm — вне контура.
2. **Анализ = черновик постмортема + рекомендации.** Автоправок материалов
   и коммитов нет; выход — один markdown-черновик на занятие.
3. **Доступ учеников — share-ссылка Zoom в группу MAX.** Пайплайн готовит
   готовое сообщение (ссылка + passcode), постит Димас. Публичный сайт
   курса для записей исключён — в кадре дети.
4. **Бэкап — QNAP по SMB.** Мак монтирует шару, пайплайн пишет rsync-ом.
   NAS в LAN, 24×7.
5. **Приватность:** имена детей заменяются на «Ученик N» по словарю из
   конфига ДО отправки транскрипта в Claude API. Медиа-файлы наружу не
   уходят вообще; транскрипция — локальным whisper.
6. **Retention облака Zoom:** записи старше 30 дней и подтверждённо
   сбэкапленные — удаляются из облака (хранилище не резиновое; ссылка в
   MAX к этому моменту отработала, архив — на NAS).

## Zoom-обвязка (ответ на «какие плагины»)

Ставить нечего — ни плагинов, ни Zoom Apps. Нужны настройки и один API-ключ:

- Аккаунт: включить **Cloud Recording** и **Audio transcript**; в шаблоне
  повторяющейся встречи курса — **автозапись в облако** (занятие пишется
  без ручного «Record»).
- Zoom Marketplace: создать **Server-to-Server OAuth app**; scopes:
  `cloud_recording:read:*` (забор), `cloud_recording:write:*` (retention).
  Account ID / Client ID / Client Secret — в `~/.junior_it/zoom.env`
  (вне репо; в репо — `zoom.env.example` с плейсхолдерами).
- **Zoom AI Companion не включаем** — анализ свой: приватнее и заточен под
  методологию курса.

## Архитектура

`tools/zoom_pipeline/` — python (3.11+, зависимости: `requests`; whisper —
внешний бинарь). Запуск — launchd-агент `com.juniorit.zoom-pipeline`
(plist в `provisioning/`), интервал 1 час. Каждый тик идемпотентен.

```
tools/zoom_pipeline/
├── pipeline.py        оркестратор тика: poll → download → backup →
│                      transcribe → analyze → drafts
├── zoom_api.py        S2S OAuth token, list/download/delete recordings
├── anonymize.py       словарь имён → «Ученик N» (чистая функция)
└── config.py          пути, словарь имён, retention; читает
                       ~/.junior_it/zoom-pipeline.toml
```

Состояние — `~/.junior_it/zoom-state.json`: обработанные meeting UUID и
их фазы. Вне репо, как и конфиг с секретами.

### Поток тика

1. **Poll:** `/users/me/recordings?from=<-7d>` → встречи, чьих UUID нет в
   state или чья фаза не завершена.
2. **Download:** mp4 + m4a + vtt (если есть) → `recordings/YYYY-MM-DD/`
   (каталог уже в .gitignore). Докачка при обрыве — переизвлечение файла
   целиком, файлы конечного размера.
3. **Backup:** rsync на смонтированную шару QNAP (путь в конфиге,
   например `/Volumes/backup/JuniorIT/recordings/`). Шара не смонтирована
   или rsync упал → лог, фаза не продвигается, ретрай следующим тиком.
   Фазы дальше backup не идут, пока бэкап не подтверждён.
4. **Transcribe:** mlx-whisper (large-v3, Metal на M1 Ultra, запуск через
   `uvx`) по m4a → `transcript.txt` рядом с записью (и в бэкап). Облачный
   vtt — fallback, если whisper недоступен.
5. **Analyze:** транскрипт → `anonymize` → `claude -p` с транскриптом и
   `playground/<дата>/session.yml` (если файла нет — анализ без сверки с
   планом, с пометкой). Выход: `meta/drafts/lesson-YYYY-MM-DD-analysis.md`:
   - фактические тайминги блоков против манифеста, где буксовали;
   - сработал ли cutting_plan;
   - рекомендации к следующему занятию;
   - черновик постмортема по форме `/postmortem`;
   - черновик сообщения в MAX: тема занятия, share-ссылка, passcode
     (языковые правила parent-msg: без запрещённой лексики).
6. **Retention:** записи из state старше 30 дней с подтверждённым бэкапом —
   `DELETE` в облаке Zoom, пометка в state.

`meta/drafts/` — добавить в `.gitignore`: черновики содержат ссылки с
passcode и обсуждение конкретного занятия; в репо попадает только то, что
Димас руками перенёс в постмортем.

### Уведомление

По завершении анализа — macOS-нотификация (`osascript`) со ссылкой на
черновик. Никаких сообщений в MAX сам пайплайн не шлёт.

### Ошибки

Сетевые вызовы — с таймаутами; whisper и claude -p — с таймаутом процесса;
любой сбой фазы логируется в `~/Library/Logs/junior-it-zoom.log` и
повторяется следующим тиком (фазы в state — идемпотентность). Полингов без
лимита нет: тик делает один проход и умирает.

## Проверка

- pytest в `tools/tests/`: state-машина фаз (новая запись, обрыв на бэкапе,
  ретрай), `anonymize` (словарь, регистры, падежи по стем-совпадению),
  парсинг ответа recordings API (фикстура JSON), retention-отбор.
  Сеть и whisper в тестах мокаются.
- Ручной прогон: `pipeline.py --dry-run` (показывает план действий без
  скачивания/удаления) и `pipeline.py --once` (один тик руками).
- Валидации CI не добавляем: пайплайн живёт на маке, в деплой сайта не
  входит.

## Вне скоупа

Webhook-и Zoom (нужен публичный endpoint), веб-интерфейс к архиву NAS,
автопостинг в MAX, авто-правка материалов курса, обработка старых записей
из ~/Documents/Zoom и recordings/ (разовая миграция — отдельным решением
после обкатки).
