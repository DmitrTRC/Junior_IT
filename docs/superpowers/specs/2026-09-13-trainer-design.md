# Тренажёр — дизайн

Дата: 2026-09-13. Статус: принят Димасом (брейншторм в сессии).
Наследует раздел «Тренажёр» из `2026-09-09-course-restructure-design.md`:
статика на GH Pages, банк `textbook/quizzes/*.json`, схема вопроса
`id/source/type/q/options/answer/why/terms`, 7 типов, режимы Тренировка
и Зачёт, `localStorage`, без бэкенда, `why` обязательно.

Дедлайн: зачёт по главе 1 (7 класс) — занятие 30.09.2026.

## Решения этой спеки

1. **Зачёт — билет со стратифицированной выборкой.** 15 вопросов, по 3 с
   каждого из пяти параграфов главы 1, случайно. Каждый прогон — новый билет.
2. **Порог — ≥80% (≥12/15) = сдано.** Зачёт/незачёт, без оценок и рейтингов.
   Пересдача разрешена, каждая попытка фиксируется.
3. **Банк главы 1 — учебник + наши.** Все тестовые задания учебника
   (5 параграфов × ~10) плюс ~10–15 наших вопросов (`source: "junior_it"`)
   редких типов (`match`, `order`, `number`). Наши вопросы участвуют в зачёте
   наравне с учебником.
4. **Ответы — по ключу учебника** («Ответы к вопросам и заданиям», конец
   книги). Черновик банка собирается из OCR
   (`~/Library/Caches/junior_it_ocr/7kl.txt`), вычитка Димаса — сверка;
   OCR врёт в формулах и коде.
5. **Анти-чита нет.** Ответы лежат в JSON открыто; зачёт проходит на занятии
   под шарингом экрана — этого достаточно.

## Данные

Файл на параграф, наши вопросы — в тех же файлах:

```
textbook/quizzes/
├── index.json      манифест: глава → параграфы → файлы (руками)
├── 07-1.1.json
├── ...
└── 07-1.5.json
```

Файл параграфа: шапка `{grade, chapter, paragraph, title}` + `questions[]`
по схеме первой спеки. `id` вида `07-1.1-04`, `source` вида
«7 кл, §1.1, тест 4» либо `junior_it`. Манифест нужен потому, что статике
нечем прочитать каталог.

## Архитектура

Vanilla ES-модули, без сборки. Банк читается `fetch`-ем — работает на GH Pages
и через `python3 -m http.server` локально (не через `file://`).

```
trainer/
├── index.html      оболочка, три экрана
├── trainer.css     на токенах meta/brand-tokens.css
└── js/
    ├── engine.js   чистая логика, без DOM: билет, проверка, скоринг
    ├── ui.js       экраны, рендер типов вопросов, события
    └── storage.js  localStorage, строка результата
```

### engine.js (тестируется node --test)

- `buildTicket(bank, rng)` — 3×5 стратифицированная выборка, перемешивание;
  rng передаётся параметром (в тестах — детерминированный, в бою —
  `Math.random`).
- `checkAnswer(question, answer)` — все 7 типов. `text` — нормализация:
  trim, нижний регистр, ё→е. `multi`/`match`/`order` — полное совпадение,
  без частичного зачёта.
- `score(results)` — процент, разбивка по параграфам, `passed = correct >= 12`
  при билете 15 (порог 80%, округление вверх).

### Режимы

**Тренировка**: охват — параграф или вся глава; вопросы вперемешку; ответ →
сразу подсветка + `why`; ошибочный вопрос встаёт в конец очереди и
повторяется, пока не решён верно. В localStorage не пишет.

**Зачёт**: линейно, без возврата к предыдущим вопросам, без подсказок;
`why` не показывается по ходу. В конце — экран итога.

## UI

Три экрана в одном `index.html`:

1. **Старт** — имя (спрашивается один раз, хранится), выбор охвата,
   две крупные кнопки «Тренировка» / «Зачёт» (зачёт — всегда вся глава),
   внизу — последние попытки зачёта.
2. **Вопрос** — прогресс «4 из 15», карточка вопроса, рендер по типу.
   В Тренировке после ответа — подсветка и плашка `why`.
3. **Итог зачёта** — процент, «сдано / пока нет», разбивка по параграфам,
   кнопка «Скопировать результат».

Бренд: тёмная тема, токены из `meta/brand-tokens.css`, акцент — трек `book`
(`--track-book #7aa2ff`), Rubik / Manrope / JetBrains Mono. Код в
`find-error` — Dracula-палитрой, как в уроках. Адаптив, без хрупких
`position:absolute`. Перед коммитом — brand-check.

## Хранение и результат

`localStorage["jit-trainer"]`:

```json
{
  "name": "Имя",
  "attempts": [
    {"date": "2026-09-30", "chapter": "07-1", "size": 15, "correct": 13,
     "byParagraph": {"1.1": [3, 3], "1.2": [2, 3]}, "passed": true}
  ]
}
```

`byParagraph` — пары `[верно, всего]` по каждому параграфу билета.

Строка для MAX (кнопка «Скопировать»):

```
Зачёт · 7 кл, глава 1 · 13/15 (87%) · сдано · §1.1 3/3 · §1.2 2/3 · §1.3 3/3 · §1.4 3/3 · §1.5 2/3 · 30.09.2026 · Имя
```

## Хвосты (в этот же план)

- Плашка «Тренажёр — скоро» на лендинге (`index.html:530`) → живая ссылка
  на `trainer/`.
- `build_site.sh` — перевести с чёрного списка на белый: публикуется только
  перечисленное; состав белого списка — текущий фактически публикуемый набор,
  сверить при реализации.
- `course-map.json` — добавить дату прохождения из `session.yml`
  (`completed`) в контракт: хронология «свежих шпаргалок» на лендинге.
  Генератор `tools/build_course_map.py`.

## Проверка

- `tools/trainer-tests/engine.test.mjs` — `node --test`: скоринг всех 7 типов
  (верный / неверный / пограничный), стратификация билета с детерминированным
  rng, порог, формат строки результата.
- `tools/validate_quizzes.py` — схема банка: `why` непустой, `answer` в
  диапазоне `options`, id уникальны, параграф файла совпадает с шапкой.
  Запускается в деплой-workflow перед сборкой сайта (падение — нет деплоя).
- Ручной прогон: `python3 -m http.server 8000` → `/trainer/`.

## Вне скоупа

Задачи на код (настоящий `python3`/`pytest`) — отдельная часть гибрида, не
этот тренажёр. Банки глав 2+ и 8 класса — после обкатки главы 1. Спорт-механик
(таймеры, очки за скорость, стрики) не будет сознательно.
