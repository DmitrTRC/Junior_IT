# Коммуникации курса (comms) — дизайн

Дата: 2026-09-28. Статус: принят Димасом (брейншторм в сессии).

Подсистема доставки: объявления, домашки и ответы ученикам идут через
Telegram, сдача домашек — через GitHub, материалы и домашки канонически
лежат на сайте курса (GitHub Pages). MAX остаётся ручным дублем. Ничего
не уходит детям и в группу без кнопки «отправить», нажатой Димасом.

Повод: опрос 27.09 — все ученики живут в Telegram (через VPN), сообщения
в MAX пропускают. Домашка после 20.09 не ушла вовсе, потому что «текстом
вечером» не работает.

## Решения

1. **Адресаты — все в Telegram**: дети и родители в одной группе курса,
   сдачи и вопросы — каждый ребёнок боту в личку. MAX — ручной дубль:
   бот присылает Димасу готовый текст «для MAX», копирует он.
2. **Хостинг — HP Elite 800 дома**, 24×7 (UPS + генератор), Linux с
   systemd. Telegram — через shadowsocks-клиент с Outline-ключом Димаса
   (SOCKS5 на localhost). Обрыв сети на 7–10 минут при переключении
   питания — штатная ситуация, не сбой.
3. **«Почтальон и мозг».** HP (`courier`) — только транспорт и очереди,
   о курсе не знает. Mac (`brain`, `tools/comms/`) — журнал, репо,
   `claude -p`, генерация рассылок; тик launchd раз в минуту, как у
   Zoom-пайплайна. Mac спит — очередь ждёт.
4. **Роль Claude — черновики.** Ответ ребёнку, отзыв на домашку, пост в
   группу: сначала Димасу с кнопками «отправить / править / отбросить».
   Детям напрямую — никогда.
5. **Сдача — через GitHub**: у каждого ученика свой приватный репозиторий
   из шаблона курса, Димас — collaborator; brain опрашивает коммиты и гоняет
   `pytest`. Telegram несёт только копию задания и ссылку на страницу.
   Скриншот боту в личку — временный путь до урока про `git`.
6. **Домашка публикуется на сайт при подготовке урока**: `homework/<id>/`
   становится страницей ученика; готовность страницы — пункт бокса
   «готовность» info-панели.
7. **Регулярного техчека нет.** Скриншот `python3 --version` — разовое
   действие после настройки машины, не часть рассылок.
8. **Roadmap с первого дня**: `courier` пригоден для любого курса; курсовая
   специфика brain — в одном адаптере и одном toml. Подробно — в конце.

## Границы

- Zoom-пайплайн не меняется: brain сам читает новые файлы в `meta/drafts/`
  и превращает раздел «Сообщение в MAX» в черновик поста.
- Ядро журнала (`tools/journal/`) не меняется: brain вызывает `cli.py`.
  В ростер добавляются поля (ниже).
- Сайт: добавляется генератор страниц домашек и правило сборки; лендинг
  и модули не трогаем.
- Не строим: MAX API, почту, веб-панель, автоответы детям, разбор
  скриншотов, несколько курсов на одном боте, контейнеры.

## Архитектура

```
Telegram ⇄ [HP: sslocal → courier (aiogram, long-polling)] ⇄ queue/ ⇄ ssh/rsync ⇄ [Mac: brain tick] ⇄ journal, playground, meta/drafts, claude -p, gh api
```

### `courier/` — почтальон (HP)

Отдельный Python-пакет в корне репо (свой `pyproject.toml`, Python 3.12,
aiogram 3, aiohttp-socks). Один процесс под systemd, пользователь
`courier`, рабочий каталог `/srv/courier/`.

Обязанности, и только они:

- **Доставка**: элементы из `queue/outbox/` → Telegram (текст, файлы,
  inline-кнопки, ответ на сообщение). Успех → `queue/sent/` с `message_id`.
- **Приём**: всё входящее → `queue/inbox/`: текст, фото, документы
  (файлы скачиваются с Telegram в каталог элемента), нажатия кнопок,
  ответы Димаса на пересланные сообщения.
- **Регистрация**: `/start <код>` — связывает `telegram_id` с непрозрачным
  `comms_id` из `registry.json`. Незарегистрированным бот не отвечает.
  В группе реагирует только на упоминание или reply на своё сообщение.
- **Сторожок**: heartbeat Димасу раз в сутки в 09:00 («жив, очередь: n»);
  после обрыва связи дольше 2 минут — «был в отключке N минут»;
  если brain не заходил дольше 30 минут (mtime `queue/.last_pull`) —
  «мозг молчит», один раз до возобновления.

Конфиг `/srv/courier/courier.toml`: `group_chat_id`, `teacher_telegram_id`,
`proxy = "socks5://127.0.0.1:1080"`, интервалы. Секрет
`/srv/courier/courier.env`: `BOT_TOKEN`, права 0600. Имён, ростера,
материалов на HP нет.

### `tools/comms/` — мозг (Mac)

launchd-агент `com.juniorit.comms`, `StartInterval 60`, лог
`~/Library/Logs/junior-it-comms.log`, конфиг `~/.junior_it/comms.toml`
(адрес HP, путь очереди, курс, репо), состояние
`~/.junior_it/comms-state.json`.

Тик:

1. `pull` — `rsync --remove-source-files` `inbox/` с HP в
   `~/.junior_it/comms-inbox/`, `touch .last_pull` на HP.
2. `apply` — каждый входящий элемент по `kind` (сдача, вопрос, кнопка,
   команда, heartbeat) → действия: журнал через `cli.py`, черновик через
   `claude -p`, элементы в локальный `outbox-staging/`.
3. `schedule` — по часам и состоянию: напоминание накануне (12:00 за день
   до ближайшего `session.yml`), сводка хвостов (18:00), новый черновик
   анализа в `meta/drafts/` → пост.
4. `github` — каждый пятый тик: опрос репозиториев учеников, тесты.
5. `push` — `outbox-staging/` → `queue/outbox/` на HP (каталог вложений
   первым, JSON последним — courier берёт элемент только по JSON).

Курсовая специфика — в одном модуле `tools/comms/course.py` (где
`session.yml`, как звать журнал, адрес материалов, шаблоны текстов).
Остальной код курса не знает.

### Очереди

`/srv/courier/queue/{outbox,sending,sent,inbox,failed}/`. Элемент —
`<ulid>.json` плюс каталог `<ulid>/` с вложениями. Переходы между
каталогами — `rename`, атомарно. Courier при старте досылает всё из
`sending/`.

## Данные

### Ростер (`students/roster.yml`, приватно)

К ученику и родителю добавляются:

```yaml
comms_id: "s-7f3a"                 # непрозрачный id для HP
telegram_id: 123456789             # после /start
telegram_code: "KX7-42"            # код регистрации, выдаётся лично
github: {user: "…", repo: "owner/name"}   # только у ученика
```

### Реестр на HP (`/srv/courier/registry.json`)

`{"codes": {"KX7-42": "s-7f3a"}, "ids": {"123456789": "s-7f3a"}}` —
brain пишет коды, courier — привязки. Имён нет.

### Элементы очередей

Исходящий:

```json
{"id": "01J…", "to": "group | s-7f3a | teacher", "text": "…",
 "parse_mode": "HTML", "files": ["broken.py"],
 "buttons": [{"label": "отправить", "data": "send:01J…"}],
 "reply_to": 4711, "created": "2026-09-28T12:00:00+03:00"}
```

Входящий:

```json
{"id": "01J…", "from": "s-7f3a | teacher | unknown:123", "chat": "private | group",
 "kind": "text | photo | document | callback | reply | heartbeat",
 "text": "…", "files": ["photo.jpg"], "message_id": 4712,
 "reply_to_item": "01J…", "callback": "accept:01J…", "ts": "…"}
```

`callback_data` — `<действие>:<id элемента>`, укладывается в 64 байта.

### Состояние brain (`comms-state.json`)

Обработанные id входящих (последние 30 дней), `reminder_sent_for`,
`digest_sent_on`, `drafts_seen`, `github: {"s-7f3a": {"sha": "…", "polled": "…"}}`,
ожидающие черновики: `id → {kind, target, hw_id, …}`.

## Потоки

1. **Регистрация.** Димас: `cli.py comms code <student>` → код в ростер и
   `registry.json`; выдаёт лично. `/start <код>` → бот: «привязал»;
   Димасу: «ученик s-7f3a зарегистрирован» (brain подставляет имя).
2. **Накануне.** Черновик Димасу: время, тема, ссылка на материалы.
   «Отправить» → группа.
3. **После занятия.** Новый `meta/drafts/lesson-*-analysis.md` → brain
   собирает пост: раздел «Сообщение в MAX» + домашка из `session.yml`
   (текст `task.md` в Telegram-HTML, ссылка на страницу, срок `due`,
   вложения) → Димасу с кнопками. После «отправить» — второе сообщение
   Димасу «дубль в MAX».
4. **Сдача через GitHub.** Локальный bare-клон каждого репо ученика в
   `~/.junior_it/hw-repos/<comms_id>/`; `git fetch`; новые коммиты, тронувшие
   `hw/<id>/` → `git archive` подпапки во временный каталог → `pytest`
   из `homework/<id>/tests/` (cwd — временный каталог, таймаут 30 с) →
   журнал `hw <дата> <id> <student> submitted --by github --note "sha, тесты
   3/3"` → Димасу: «ученик сдал python-01: тесты 3/3» и кнопки
   «принято / доработать / Claude, разбери». Переходный путь: файл боту в
   личку → `submitted --by telegram`, без тестов; отключается конфигом
   после урока про `git`.
5. **Кнопки Димаса.** «Принято» → `accepted` (баллы по тарифу считает
   журнал), ребёнку «принято ✓». «Доработать» → Димас отвечает текстом на
   это сообщение → `rework`, текст ребёнку. «Claude, разбери» → черновик
   отзыва → Димасу с кнопками «отправить / отбросить».
6. **Вопрос ребёнка** (личка или упоминание в группе) → Димасу с кнопками
   «отвечу сам» (его reply уходит ребёнку от бота с подписью «Димас») и
   «Claude» (черновик → кнопки).
7. **Команды Димаса** в личке боту: `/claude <задача>` → черновик
   (сводка сдач, хвосты, текст родителям по правилам parent-msg,
   напоминание группе). `/status` → длина очередей, последний тик,
   последний heartbeat.
8. **Хвосты.** 18:00 ежедневно: журнал → просроченные без сдачи → Димасу
   сводка с кнопкой «напомнить» по каждому → ребёнку в личку.

## Публикация домашек на сайт

Генератор `tools/build_homework_pages.py`: `homework/<id>/task.md` →
`homework/<id>/index.html` в бренде (токены из `meta/brand-tokens.css`,
как шпаргалки), вложения — все файлы каталога кроме `task.md` и `tests/`.
`tools/build_site.sh` добавляет `homework/` в публикацию с исключением
`tests/`. Адрес: `https://dmitrtrc.github.io/Junior_IT/homework/<id>/`.
Бокс «готовность» info-панели: домашка плана без `index.html` — красная.
Страницы — через brand-check до коммита.

## Отказы

- Сеть на HP: long-polling с растущей паузой до 60 с; Telegram хранит
  апдейты у себя; 429/5xx — повтор; после 5 неудач элемент → `failed`,
  Димасу сообщение.
- Mac спит: очередь копится на HP, brain разбирает по порядку.
- Идемпотентность: ULID у элементов, обработанные id в состоянии; повтор
  кнопки → «уже сделано»; повторный `git fetch` без новых sha — ничего.
- GitHub недоступен: опрос пропущен, лог.
- `claude -p` упал или пустой ответ: Димасу «черновик не получился»,
  элемент в `failed`.
- Время — Europe/Moscow везде.

## Безопасность и приватность

- HP: отдельный пользователь, ssh только с Mac по ключу (ключ Mac → HP,
  обратного нет), `courier.env` 0600. Данные — `telegram_id`, коды,
  очереди; имён нет.
- Бот отвечает только зарегистрированным; команды — только с
  `teacher_telegram_id`.
- Ключ Anthropic не нужен: `claude -p` под сессией Димаса, промпты в
  `tools/comms/prompts/*.md` с запретом файловых операций, как в
  `analysis_prompt.md`. gh-токен на Mac уже есть.
- Код учеников: временный каталог, таймаут, без прав на репо; контейнер —
  roadmap.
- В публичном репо — только код и тесты без имён и id; живое — в
  `students/` и `~/.junior_it`.
- Возраст: GitHub требует 13+; младше — аккаунт на родителя, для системы
  разницы нет.

## Тесты (`tools/tests/test_comms_*.py`, `courier/tests/`, pytest)

- Очереди: атомарный переход, порядок «вложения, потом JSON», досыл из
  `sending/`.
- Courier: обработчики с моком Bot API — регистрация, фильтр
  незарегистрированных, кнопки, reply Димаса, heartbeat и «мозг молчит».
- Brain: фейковые входящие → ожидаемые вызовы `cli.py` и элементы
  исходящей; расписание по часам; извлечение раздела из черновика анализа;
  Telegram-HTML из `task.md`; опрос GitHub на локальном bare-репо; раннер
  `pytest` на `homework/python-01-first-run`.
- Приёмка: тестовый бот и тестовая группа (`courier-test.env`), тестовый
  аккаунт ученика: регистрация → пост → коммит → журнал → кнопка → ответ.

## Проверка (готово, когда)

1. Пост после занятия и домашка ушли в группу одной кнопкой; текст для
   MAX пришёл Димасу следом.
2. Коммит в репо ученика через ≤ 5 минут отражён в журнале с результатом
   тестов, Димас получил кнопки, ребёнок — ответ после нажатия.
3. Вопрос ребёнка → черновик Claude → ребёнок получил ответ только после
   кнопки.
4. Выключение сети на 10 минут: ничего не потеряно, Димас получил «был в
   отключке».
5. Страница домашки открывается по постоянному адресу до занятия.

## Roadmap: от MVP к системе для любого курса

Держим при каждом решении MVP, делаем позже:

- `courier` — отдельный репозиторий и пакет: `pip install` + systemd-unit +
  `courier.toml`, развёртывание на любом Linux за десять минут; затем
  docker-compose (courier + sslocal).
- Транспорт как интерфейс: Telegram сейчас, MAX API и почта — теми же
  очередями, courier выбирает канал по полю `to`.
- Один courier на несколько курсов и ботов: префикс курса в очередях.
- Brain: `course.py` превращается в плагин курса, `comms.toml` описывает
  курс целиком (где план, где журнал, где материалы).
- Песочница для кода учеников — контейнер.
- Веб-панель Димаса поверх очередей и журнала — только когда Telegram
  перестанет вмещать.
