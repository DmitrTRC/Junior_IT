# Программа курса на год: данные, страница, три ракурса

Дата: 2026-09-29. Статус: черновик на ревью Димаса.

## Зачем

Родители и ученики спрашивают оглавление курса целиком. Сейчас на сайте
только карта из существующих модулей, программа на год нигде не собрана.
Нужна одна страница `program.html` с переключателем ракурса
«Ученику / Родителям / Почему так» и один источник данных, из которого
собираются страница, лендинг и текст для мессенджера.

Горизонт: учебный год 2026/27, по месяцам, сентябрь 2026 — май 2027.
Второй год — одним абзацем «куда дальше».

Цель года (двойная, обе части в программе явно):
1. свой проект на Python на GitHub с тестами и README;
2. учебник Босовой 7 класса закрыт с опережением школы, начало 8-го
   (системы счисления, логика, алгоритмы, чтение Паскаля).

**Курс живой.** Темп подстраивается под занятость и успехи учеников,
порядок тем внутри года может сдвигаться, состав модулей меняться. Не
меняется цель года. Эта оговорка живёт в данных (`disclaimer`) и
показывается во всех трёх ракурсах, не только родителям.

## Что не делаем

- Не создаём сами будущие модули: программа ссылается на slug, модуль
  появится своим `module.yml` позже и подхватится автоматически.
- Не считаем прогресс по ученикам, только общий по группе (как карта курса).
- Не шлём программу в Telegram автоматически: генератор умеет отдать
  плоский текст, отправка руками. Подсистема коммуникаций может взять
  `program.json` позже.
- Никаких имён детей в данных и на странице.

## Данные: `meta/program.yml`

Один файл, внутренняя кухня (`meta/` на сайт не попадает, генератор читает
его при сборке, как `playground/` для карты курса). Идентификаторы
английские, тексты русские, термины парой «русский (english)».

```yaml
year: "2026/27"
goal:
  student: "К маю — своя программа на GitHub с тестами, которую не стыдно показать."
  parents: "К маю ребёнок пишет программы на Python, ведёт проект на GitHub с автотестами и закрывает учебник 7 класса с опережением школы."
disclaimer: "Программа живая: темп подстраивается под занятость и успехи учеников, порядок тем может сдвигаться. Цель года не меняется."
next_year: "Восьмой класс: ..."          # один абзац
principles:                              # ракурс «Почему так», общие
  - "Учебник идёт с опережением школы на 2–6 недель: в классе ребёнок узнаёт, а не открывает."
  - ...
blocks:
  - month: "2026-10"                     # YYYY-MM, уникален, по возрастанию
    title: "Программа спрашивает и решает"
    modules:
      - python/m-02-variables            # строка: модуль есть или будет
      - {id: devops/m-03-github, title: "GitHub: репозиторий домашек (remote)", track: devops}
    outcome: "Программа-диалог с ветвлением; домашки сдаются в своём репозитории на GitHub."
    textbook: ["7:1.2", "7:1.3", "8:5.2", "8:5.4"]
    trainer: ["7:1"]                     # зачёты и тренажёр по главам, необязательно
    why: "Git и GitHub в октябре, а не в конце: с ноября домашки живут в репозитории."
    events: ["мини-проект: викторина, 2 занятия"]   # необязательно, не-модульные вехи
```

Правила разрешения модулей:
- `modules` может быть пустым, если месяц состоит из событий (май:
  спринт, релиз, демо-день); тогда обязателен непустой `events`.
- Элемент `modules` — либо строка с id, либо объект `{id, title, track}`.
- Если `tracks/<id>/module.yml` существует, берём оттуда `title`,
  `minutes`, ссылки и статус из карты курса; `title`/`track` в объекте
  тогда лишние, тест это отлавливает как ошибку.
- Если модуля на диске нет, `title` и `track` обязательны, статус
  `planned`, ссылок нет. `track` — один из шести треков карты.
- Каждый core-модуль из `tracks/` (кроме архивного `web`) обязан
  встречаться в программе ровно один раз, иначе тест падает: программа
  не может отставать от репозитория.

Ссылки на учебник: `"7:1.2"` — параграф, `"7:1"` — глава.
Подписи: `7 кл §1.2`, `7 кл гл. 1`. Формат тот же, что в `module.yml`.

## Генератор: `tools/build_program.py`

`build_program(repo_root, today) -> dict`, переиспользует `load_modules`,
`load_sessions`, `module_statuses`, `module_links` из `build_course_map.py`.

Выход `program.json`:

```json
{
  "generated_at": "...", "year": "2026/27",
  "goal": {"student": "...", "parents": "..."},
  "disclaimer": "...", "next_year": "...", "principles": ["..."],
  "current_month": "2026-09",
  "blocks": [
    {
      "month": "2026-10", "label": "Октябрь", "status": "upcoming",
      "title": "...", "outcome": "...", "why": "...",
      "textbook": [{"ref": "7:1.2", "label": "7 кл §1.2"}],
      "trainer": [{"ref": "7:1", "label": "7 кл гл. 1"}],
      "events": ["..."],
      "modules": [
        {"id": "python/m-02-variables", "title": "...", "track": "python",
         "status": "planned", "minutes": null, "links": {}}
      ]
    }
  ]
}
```

Статус блока по календарю: месяц раньше `today` — `done`, текущий —
`current`, позже — `upcoming`. Статус модуля — из карты курса
(`done` / `current` / `planned`); для модулей без `module.yml` — `planned`.
Блок «сентябрь» помечается `done` с октября автоматически, руками ничего
не двигаем.

Плоский текст для мессенджера: `program_text(program, view)` с `view`
`student` или `parents`, без markdown, короткими абзацами по месяцам;
первые три строки — заголовок, цель года под ракурс, оговорка «курс живой». CLI: `build_program.py <repo_root> <out_dir>`
пишет `program.json`; флаг `--text student|parents` печатает текст в stdout
вместо записи.

`tools/build_site.sh` вызывает генератор после карты курса, `program.html`
и `program.json` попадают в белый список публикации.

## Страница: `program.html`

В корне, рядом с `index.html`, тот же бренд: тёмная палитра лендинга,
Rubik / Manrope / JetBrains Mono, цвета треков из токенов. Vanilla JS,
`fetch('program.json')`, без сборки. Первым проектируется телефон
(родители читают ссылку из мессенджера), проверка скриншотом на 400px.

Шапка: заголовок «Программа года 2026/27», цель года в одну фразу под
выбранный ракурс, оговорка «курс живой» под ней, мелко, во всех ракурсах.

Переключатель: сегмент из трёх кнопок «Ученику · Родителям · Почему так».
Выбор пишется в hash (`#student`, `#parents`, `#why`) — ссылку можно
кинуть сразу на нужный ракурс; последний выбор запоминается в
`localStorage`. По умолчанию `#parents`.

Тело: вертикальная лента месяцев, у каждого карточка «Месяц · тема».
Текущий месяц выделен и подписан «сейчас», прошедшие приглушены.

- **Ученику:** список модулей блока строками: чип трека, название,
  статус (пройден / сейчас / впереди), у существующих — чипы материалов
  (слайды · шпаргалка · словарик · домашка), как в узле карты курса.
  Строка `events` под модулями. Учебник и «результат» не показываем.
- **Родителям:** тема, абзац `outcome`, строка «Учебник: 7 кл §1.2, …»,
  строка «Зачёт: 7 кл гл. 1» если есть. Модули не перечисляем: родителю
  важно, что ребёнок будет уметь, а не slug модуля.
- **Почему так:** сверху блок `principles` списком, затем у каждого месяца
  только `why`. Внизу абзац `next_year`.

Подвал: ссылка на лендинг и карту курса.

Лендинг: кнопка «Программа года» в hero рядом с «Карта курса» и ссылка
в блоке быстрых ссылок над картой. Узлы карты не трогаем.

## Тесты

`tools/tests/test_build_program.py`:
- строка-id существующего модуля разрешается в title/minutes/links/статус;
- объект без `module.yml` требует `title` и `track`, иначе `ValueError`;
- объект с `title` при существующем модуле — `ValueError`;
- core-модуль из `tracks/`, которого нет в программе, — `ValueError`;
  архивный `web` не требуется;
- статусы блоков по `today`: прошлый / текущий / будущий месяц;
- подписи учебника: `7:1.2` → `7 кл §1.2`, `8:1` → `8 кл гл. 1`;
- `program_text(..., "parents")` начинается с оговорки и содержит
  `outcome` каждого месяца, `student` — названия модулей;
- месяцы уникальны и отсортированы, иначе `ValueError`.

`tools/tests/test_landing.py`: hero содержит ссылку на `program.html`.
`tools/tests/test_build_site.py`: `program.html` и `program.json` в `_site`,
`program.json` содержит блок текущего месяца.
`tools/tests/test_program_page.py`: страница ссылается на `program.json`,
содержит три значения hash и id контейнера, нет слова «дружина» и
запрещённой лексики, нет имён детей.

Бренд-проверка (`/brand-check`) страницы и текстов `program.yml` до коммита.

Принципы («Почему так»):
- Учебник с опережением школы на 2–6 недель: в классе ребёнок узнаёт, а не
  открывает. Главы 3–5 седьмого класса (текст, графика, мультимедиа) без
  отдельных занятий: это навыки пользователя, закрываем тренажёром.
- Git и GitHub в октябре, а не в конце: с ноября домашки живут в
  репозитории, к маю у ребёнка год истории коммитов.
- Циклы раньше списков, функции перед первым проектом: инструмент
  появляется за месяц до того, как без него нельзя.
- Паскаль только читать: он есть в учебнике 8 класса, писать на нём не
  будем. Понадобится перевод программы — добавим модуль.
- «Компьютер изнутри» вставками между блоками кода, как передышка от
  клавиатуры.
- Курс живой: темп и порядок подстраиваются под занятость и успехи
  учеников, цель года не меняется.

`next_year`: «Восьмой класс: Python глубже (классы, модули, простые
библиотеки), проект побольше в команде из двух-трёх человек, учебник 8-го
класса целиком с тем же опережением».

## Порядок реализации (для плана)

1. `meta/program.yml` с содержимым выше и генератор с тестами.
2. `build_site.sh`, белый список, `program.json` на сайте.
3. `program.html` три ракурса, телефон первым, скриншот 400px.
4. Ссылки с лендинга, бренд-проверка, деплой.
