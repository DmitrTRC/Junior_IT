# Реструктуризация курса: учебник + Python + треки — дизайн

Дата: 2026-09-09. Статус: утверждён в чате по секциям, ждёт ревью спеки.

## Контекст и задача

Курс менял концепцию по ходу. Начинался как «первый сайт за 75 минут» для
группы 11–14 лет на вебинаре в MAX: HTML → CSS → JS, дети смотрят, делают дома.
За лето формат сместился — два спонтанных занятия один на один через Zoom
породили блок «Компьютер изнутри», и стало ясно, что дальше курс живёт в другой
форме.

Новая рамка:

- **Аудитория** — одна ученица, 7 класс. Проектируем с запасом на малую группу
  2–5 человек, 7–8 класс, но не платим за этот запас сегодня.
- **Цель** — подготовка к материалу школьного учебника с опережением плюс
  углублённое изучение отдельных тем по требованию.
- **Учебники** — Босова Л. Л., Босова А. Ю. «Информатика», 7 и 8 класс,
  базовый уровень, «Просвещение», 2022. Оба лежат в PDF (сканы без текстового
  слоя).
- **Формат занятия** — Zoom, ученица шарит свой экран и работает руками. Машина
  — Mac. Общение — MAX, код — GitHub, аккаунт у неё уже есть.
- **Расписание** — два занятия в неделю: среда и воскресенье, 20:00.
- **Смена основного языка** — вместо JS основная ставка на Python. JS и веб не
  выбрасываются, а переезжают в отдельный трек «по требованию».

### Что даёт структура учебников

**7 класс** (257 с.): гл. 1 Информация и информационные процессы · гл. 2
Компьютер как универсальное устройство обработки данных (компоненты, ПО, файлы
и каталоги, интерфейс, сети, интернет-сервисы) · гл. 3 Обработка текстовой
информации · гл. 4 Обработка графической информации · гл. 5 Мультимедиа.
Приложение: правила информационной безопасности и графика Turtle на Python 3.

**8 класс** (273 с.): гл. 1 Системы счисления · гл. 2 Элементы математической
логики · гл. 3 Основы алгоритмизации · **гл. 4 Начала программирования на
языке Паскаль** · **гл. 5 Начала программирования на языке Python**.
Приложения: отладка в PascalABC.NET, библиотека GraphABC, модуль Graph в Python.

Главы 4 и 5 восьмого класса **зеркальны**: одинаковый набор параграфов (общие
сведения о языке, организация ввода-вывода, линейные алгоритмы,
разветвляющиеся, циклические) на двух языках. Это снимает вопрос «зачем нам
Паскаль»: Паскаль преподаётся не как отдельный трек, а как **второй диалект** —
та же программа, другой синтаксис. Требование «Паскаль по верхам» закрывается
без отдельного бюджета времени, а школьные тесты по главе 4 сдаются попутно.

В каждой главе обоих учебников есть раздел «Тестовые задания для самоконтроля»
с ключами в конце книги. Это готовый банк для тренажёра.

## Принятые решения

1. **Две оси вместо одной.** `tracks/` — библиотека модулей по направлениям,
   `playground/` — журнал реальных занятий. Занятие собирается как плейлист из
   модулей. Причина: на занятии 1:1 смешиваются учебник, Python и терминал —
   «урок одного трека» не описывает реальность. Линейная нумерация уроков уже
   дала сбой (`02b`…`02g`, отдельная серия `cs-NN`) и не позволяет доставать
   материал вне очереди.
2. **Модуль — единица библиотеки**, не урок. У модуля есть тема, уровень
   (`core` / `deep` / `optional`), длительность и связь с параграфами учебника.
   Порядок задаётся плейлистом занятия, а не именем папки. «Углубить тему
   динамически» = вытащить модуль уровня `deep` вне очереди.
3. **Разделение ролей — тремя папками внутри модуля:** `shared/`, `student/`,
   `teacher/`. Роль видна сразу, и `teacher/` целиком исключается из деплоя.
4. **Эталонные решения не хранятся в публичном репозитории курса.** Живут в
   приватном репо-спутнике `Junior_IT-keys` и попадают к ученице только после
   merge её pull request.
5. **Все идентификаторы — английские.** Никакой транслитерации в именах папок,
   файлов, полей и веток: `m-03-branching`, не `m-03-vetvlenie`.
6. **Термины подаются парой ру/en.** Везде, где учебник вводит термин, рядом
   стоит принятое в индустрии английское слово: «Ветвление (branching)»,
   «Исполнитель (executor)», «ИЛИ (OR)». Это отдельная методическая цель, а не
   украшение.
7. **Тренажёр — гибрид.** Викторина по тестам учебника и нашим вопросам —
   статика HTML/JS на GH Pages, без Python-рантайма. Задачи на код — настоящий
   `python3` и `pytest` на её маке. Одна среда для кода, а не две.
8. **Домашка — ветка, pull request и CI.** Зелёная галка GitHub Actions означает
   «сдано», ревью преподавателя — про качество, не про правильность. git
   вводится тремя ступенями, а не разом.
9. **Репозиторий ученицы публичный, без персональных данных.** Имя без фамилии,
   без школы, посёлка и возраста. Публичность даёт зелёную стену контрибуций,
   бейджи и портфолио — основу системы поощрений.
10. **Опережение: на главу по теории, на год по коду.** Теория 7 класса идёт
    впереди школы, программирование берётся из 8 класса.
11. **PDF учебников не коммитятся.** Чужой копирайт и 53 МБ. Живут в `refs/`,
    добавленном в `.gitignore`. В репозитории — только производные: атлас, банк
    тестов, errata.
12. **Старые URL не ломаются.** Ссылки на уроки уже разосланы родителям; на
    прежних путях остаются редирект-заглушки.

### Анатомия модуля

```
tracks/python/m-04-branching/
├── module.yml
├── shared/      слайды, демки, живой код — то, что видно на экране
├── student/     шпаргалка, глоссарий, домашка-стартер
└── teacher/     сценарий с таймингом, ответы, «где залипнет»
```

`module.yml`:

```yaml
id: python/m-04-branching
title: "Ветвление (branching): if / elif / else"
track: python
level: core                  # core | deep | optional
minutes: 25
textbook: [8:3.5, 8:5.4]     # какие параграфы закрывает
requires: [python/m-03-types-and-math]
terms:
  - {ru: ветвление,         en: branching}
  - {ru: условный оператор, en: conditional / if-statement}
  - {ru: истина/ложь,       en: true/false, note: "bool, не «да/нет»"}
quiz: textbook/quizzes/08-3.5.json
homework: homework/python-04-branching
```

Номер в имени модуля назначается в порядке создания внутри трека и служит только
для сортировки в библиотеке. Порядок прохождения задаёт плейлист занятия, и
модуль с бо́льшим номером может быть взят раньше.

Поле `terms` — источник истины: из него собирается глоссарий модуля и
двуязычные подписи в шпаргалке. Скрипт-валидатор проверяет, что все `requires`
существуют, `quiz` и `homework` указывают на существующие файлы, а каждый
параграф из `textbook` отмечен в соответствующем атласе.

Модули блока `cs` сохраняют два отступления, зафиксированные ранее: «живая
схема» вместо живого кодинга и одна интерактивная демка вместо трёх эстетик.

## Работа с учебником

### Атлас

`textbook/atlas-07.md` и `atlas-08.md` — таблица соответствия:

| § | Тема | Наш модуль | Статус | Школа проходит | Δ |
|---|---|---|---|---|---|
| 1.3 | Представление информации | `book/m-03-signs` | закрыт | ~октябрь | +5 нед |

Статусы: `запланирован` / `закрыт` / `пропускаем осознанно` (с причиной).
Колонка Δ — измеритель опережения. Правило: модуль ставится в плейлист не позже
чем за две недели до того, как параграф начнут в школе.

### Errata

`textbook/errata.md` — накопительный файл. У каждой записи обязательны четыре
поля:

> **7 кл, §1.5.1 — «1 Кбайт = 1024 байта»**
> **Учебник:** 1 Кбайт = 1024 байта.
> **В жизни:** производители дисков считают 1 КБ = 1000 байт (SI), а 1024 байта
> — это КиБ, кибибайт (IEC). Отсюда «купил диск на 1 ТБ, система показывает
> 931 ГБ».
> **Говорим ей:** учебник даёт одну из двух систем и не называет её.
> **В школе отвечай:** 1024. Это не ложь, это другая система, и на контрольной
> ждут именно её.

Последнее поле обязательно и не подлежит смягчению: наша правда не должна
валить ей контрольную. Цель — знать обе версии и понимать разницу.

Кандидаты, видимые уже сейчас:

- 7 кл, §1.5.1 — КБ против КиБ (см. выше).
- 7 кл, приложение — `from turtle import *`. Звёздный импорт тянет в
  пространство имён всё подряд; в реальном коде так не пишут.
- 7 кл, §1.1.2 — «виды информации по способу восприятия» подаётся как
  единственная классификация; это одна из многих и она не про данные.
- 8 кл, приложение 3 — модуль `Graph` в Python. Его нет в стандартной
  библиотеке; программа из учебника у неё просто не запустится. Нужен рабочий
  эквивалент на `turtle` или `tkinter`.

Errata пополняется по ходу курса. Находка, сделанная ученицей, попадает в файл
с её авторством — это отдельная ачивка (см. ниже).

### Двуязычные термины

Глоссарий модуля — таблица из трёх колонок: «Учебник (рус)», «В проде (eng)»,
«Что это одной строкой». В шпаргалках и слайдах термин печатается парой:
**«Ветвление (branching)»**. Базовый словарь: ИЛИ → `OR`, И → `AND`, НЕ →
`NOT`, Исполнитель → `executor`, Присваивание → `assignment`, Массив → `array`,
Маршрут → `path`, Оператор → `statement`, Ветвление → `branching`, Цикл →
`loop`, Отладка → `debugging`.

## Домашки и проверка

### Репозиторий ученицы

Имя выбирает сама, без персональных данных. Структура:

```
├── README.md                      карточка прогресса: бейджи по трекам
├── .github/workflows/check.yml    pytest на push и pull request
├── requirements.txt               pytest
├── hw/
│   └── 02-first-run/
│       ├── task.md                условие
│       ├── solution.py            пишет она
│       └── test_solution.py       даём мы
└── sandbox/                       её эксперименты, CI сюда не заглядывает
```

### git тремя ступенями

Первый урок курса показал, что происходит, когда магии слишком много сразу
(`getElementById` стал стеной). git вводится постепенно:

1. `devops/m-02-git-first-commit` — `clone → правка → commit → push` в main.
   Проверка глазами.
2. `devops/m-03-branch-and-pr` — ветка, pull request, merge. Появляется смысл
   слова «предложить изменение».
3. `devops/m-04-ci-green-check` — включаем Actions. Зелёная галка = сдано.

К третьей ступени автоматика читается как справедливость, а не как наказание.

### Цикл сдачи

`git switch -c hw-02` → пишет решение → локально `pytest` зелёный → push →
pull request → **CI решает «сдано»**, преподаватель ревьюит **качество**.
Разделение принципиальное: машина говорит «работает», человек говорит «можно
лучше».

### Два решения как награда за merge

После вливания pull request скрипт из приватного `Junior_IT-keys` кладёт в папку
задачи:

- `solution_simple.py` — её уровень, то что она должна была написать сама, с
  комментариями «почему так»;
- `solution_pro.py` — элегантный вариант с разбором на несколько строк: что
  здесь лучше и почему;
- `REVIEW.md` — живые несколько строк от преподавателя.

Ограничение на `solution_pro.py` жёсткое: **читаемое, не трюковое**. Оно должно
вызывать «хочу научиться так писать», а не «я так никогда не смогу».
Comprehension вместо цикла с `append`, распаковка вместо индексов, осмысленное
имя вместо `a` — работает. Однострочник на вложенных генераторах — провал цели.

## Тренажёр

Статика на GH Pages, банк вопросов — `textbook/quizzes/*.json`, по файлу на
параграф или тему.

```json
{
  "id": "07-1-04",
  "source": "7 кл, гл. 1, тест № 4",
  "type": "single",
  "q": "Наименьшая единица измерения информации:",
  "options": ["бит", "байт", "Кбайт", "символ"],
  "answer": 0,
  "why": "Бит — один разряд: есть напряжение или нет. Байт — уже восемь бит.",
  "terms": [{"ru": "бит", "en": "bit"}]
}
```

Типы вопросов: `single` (выбор одного), `multi` (выбор нескольких), `number`
(ввод числа), `text` (ввод строки), `match` (сопоставление), `order` (порядок
шагов — для алгоритмов), `find-error` (выбрать ошибочную строку кода).

Режимы: **Тренировка** — объяснение показывается сразу, повторять можно сколько
угодно; **Зачёт** — без подсказок, результат фиксируется в `localStorage` и
выдаётся строкой, которую можно скопировать в MAX. Бэкенда нет.

Поле `why` обязательно у каждого вопроса. «Неверно» без объяснения — потерянная
минута.

Каждый вопрос из учебника попадает в банк с заполненным `source`, наши — с
`source: "junior_it"`. Так требование «сдать все тесты учебника» становится
измеримым: покрытие видно в атласе.

## Система поощрений

Опирается на то, что GitHub уже умеет, плюс тонкий слой сверху.

- **Зелёная галка CI** — основная валюта. Объективная и мгновенная.
- **Бейджи в её README** по трекам: `Python 3/8`, `Терминал 2/5`. Обновляются
  скриптом при merge.
- **Ачивки — редкие и именные**, не за посещаемость: «Первый зелёный CI» ·
  «Короче эталона» (её решение яснее нашего `simple`) · «Поправка к учебнику»
  (её находка попала в `errata.md` с авторством) · «Сама починила» (упавший CI
  без подсказки) · «Два диалекта» (одна задача на Python и на Паскале).
- **Стена контрибуций** — работает сама, репозиторий публичный.
- **Карта курса на лендинге** — пройденные модули загораются цветом направления.

Сознательно **не** делаем: очков за скорость, рейтингов, сравнения с кем бы то
ни было и ежедневных стриков. Стрик у школьницы гарантированно порвётся на
контрольной неделе, и вместо мотивации получится чувство проигрыша.

## Брендинг направлений

Цвет — маркер направления, а не тема оформления. Бренд остаётся тёмным и
единым; красятся акцентная полоса карточки модуля, заголовок шпаргалки и точка
на карте курса. Рядом — моноширинный чип с кодом трека: он читается в ч/б
печати и не зависит от цвета.

| Трек | Чип | Тёмный фон | Светлый фон (печать) | Токены |
|---|---|---|---|---|
| Учебник | `BOOK` | `#7aa2ff` | `#2b4fa8` | `--track-book`, `--track-book-ink` |
| Python | `PY` | `#00ffc8` | `#00806a` | `--track-py`, `--track-py-ink` |
| Pascal | `PAS` | `#ff5722` | `#b3350f` | `--track-pas`, `--track-pas-ink` |
| DevOps | `OPS` | `#00e676` | `#00803d` | `--track-ops`, `--track-ops-ink` |
| Компьютер изнутри | `CS` | `#ff0096` | `#a8005f` | `--track-cs`, `--track-cs-ink` |
| Web (архив) | `WEB` | `#8892b0` | `#4a5568` | `--track-web`, `--track-web-ink` |

Пара токенов на трек обязательна: шпаргалки уходят в печать на `--bg-light`, а
`#00ffc8` на белом нечитаем.

Существующие токены палитры не трогаются. Цвета треков переиспользуют
`--cyan`, `--orange`, `--green`, `--magenta` как значения, но получают
собственные имена — семантика «эстетика демки» уходит вместе с веб-треком в
архив, а `--green` продолжает работать и как success.

Шрифты не меняются: Rubik 700 в заголовках, Manrope в тексте, JetBrains Mono в
коде и чипах.

  бейджи в её README.

- **Автоматическая генерация модулей из OCR.** Атлас и банк вопросов собираются
  с ручной вычиткой: OCR по сканам даёт ошибки в формулах и коде.
- **Перевод главы 3 и далее семиклассного учебника** (текст, графика,
  мультимедиа) в модули. Эти главы — про офисные программы; берём их
  тренажёром и тестами, без отдельных занятий.
