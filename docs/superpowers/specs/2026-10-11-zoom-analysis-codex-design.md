# Анализ записей Zoom через Codex

Согласовано: использовать Codex CLI вместо Claude; ограничить повторы,
сохранять ошибки и принимать только структурированный анализ.

## Границы

Меняем только анализ в `tools/zoom_pipeline`, его состояние, тесты и инструкции
развёртывания. Скачивание, резервирование и транскрибация сохраняют прежнюю
последовательность. `tools/comms` в эту миграцию не входит.

LaunchAgent `com.juniorit.zoom-pipeline` уже выгружен и отключён.
Возвращаем расписание только после тестов и одного успешного пробного анализа.
Дубли в Recents архивируем после исправления через поддерживаемый интерфейс;
прямые изменения базы чатов исключены. При отсутствии такого интерфейса явно
фиксируем незавершённый этап.

## Движок

Конфигурация TOML получает секцию `analysis`: `engine = "codex"`, путь к CLI,
модель и уровень reasoning. Модель по умолчанию берётся из рабочего локального
Codex; при развёртывании её идентификатор фиксируется в конфигурации пайплайна.
Интерфейс движка допускает дальнейшие адаптеры, но реализуем только Codex.
Неизвестный движок и оставшийся `claude_cmd` дают явную ошибку конфигурации.

Отдельный `analysis.py` отвечает за подготовку вызова, получение результата,
классификацию ошибок и проверку Markdown. `phases.py` управляет переходами;
`state.py` хранит состояние попыток. Команды передаются списком без shell.

Codex запускается через `exec`, получает промпт в stdin, работает с таймаутом
900 секунд и `--ephemeral`. Финальный ответ читается из уникального временного
файла `--output-last-message`, а не из stdout с событиями или диагностикой.
Перед каждым вызовом выходной файл отсутствует; после обработки удаляется.

Анализ должен использовать исключительно текст промпта. Запуск идёт вне
репозитория, без пользовательской конфигурации, проектных инструкций, hooks,
skills и MCP. Настройки отключения инструментов проверяются по установленному
CLI и отдельным синтетическим запуском. `read-only` сам по себе не считается
запретом чтения или вызова инструментов. Если изоляция не подтверждается,
расписание остаётся отключённым: не запускаем учебные транскрипты с непроверенной
конфигурацией. Авторизация используется из существующей установки Codex.

Обезличивание транскрипта сохраняется. Тема и текст `session.yml` также проходят
обезличивание. Ссылка на запись и код доступа не нужны модели для анализа:
в промпте их заменяют стабильные маркеры, которые локально восстанавливаются
в разделе «Сообщение в MAX» после валидации. Промпты, токены авторизации,
транскрипты и сырые stderr/stdout не записываются в журнал или диагностику
ошибок состояния. Доступ к записи сохраняется только в локальных метаданных
состояния с правами 0600, чтобы анализ без Zoom мог восстановить сообщение.

## Состояние и повторные попытки

Сохраняем фазу `transcribed`, дополняя запись состоянием анализа:
`status`, `attempts`, `next_attempt_at`, `last_error_code`.
Статусы: `pending`, `running`, `retry_wait`, `blocked`, `exhausted`, `succeeded`.
Временные метки — UTC. Состояние записывается атомарно до внешнего вызова:
увеличивается счётчик, устанавливается `running`.

Не более трёх вызовов на запись в одном цикле обработки: первая попытка сразу,
вторая не раньше чем через час после первой ошибки, третья — через четыре часа
после второй. Часовой тик только проверяет срок; sleep внутри процесса нет.
Таймаут, сетевой сбой, временная недоступность сервиса и кратковременный rate limit
допускают повтор. Если сервис сообщает более поздний срок восстановления,
используется этот срок. После третьей ошибки — `exhausted`, автоматических
вызовов больше нет.

Блокировка аккаунта, отсутствие авторизации, недоступная модель, исчерпанная
квота без срока восстановления и неверная конфигурация блокируют движок целиком,
включая другие встречи и следующие тики. Неизвестная ошибка и некорректный
Markdown блокируют конкретную запись до ручного решения. Для диагностики
хранятся только нормализованные коды и номер попытки.

Один процесс держит файловую блокировку на весь тик: параллельный ручной запуск
не отправляет второй запрос. Если следующий процесс обнаружил `running`, значит
предыдущий завершился без сохранённого результата: попытка уже учтена, запись
переходит в `blocked` с кодом `interrupted`, автоматического повтора нет.
Повреждённое состояние вызывает остановку, а не сброс истории на `new`.

CLI получает явные команды возобновления: разблокировать движок либо сбросить
цикл анализа конкретной записи. Эти команды изменяют только локальное состояние
и не вызывают Zoom, модель или retention. Снятие блокировки движка не сбрасывает
индивидуальные счётчики и не разблокирует записи автоматически.

Миграция читает прежний формат состояния и сохраняет фазы. Старые записи
`transcribed` без истории попыток переводятся в `blocked` с кодом
`legacy_untracked`: неизвестное число прежних вызовов не считается нулём.
Для пробного анализа одна выбранная запись возобновляется явно; массового
автоматического прогона накопленных транскриптов нет.

## Приём результата

Успех требует нулевого exit code и непустого нового выходного файла. Документ
начинается с первого обязательного заголовка; допускается только Markdown без
внешней обёртки в code fence. Обязательные заголовки уровня 2 ровно по одному,
в указанном порядке, каждый с непустым содержимым:

1. `Фактические тайминги`
2. `Где буксовали`
3. `Cutting plan`
4. `Рекомендации к следующему занятию`
5. `Черновик постмортема`
6. `Сообщение в MAX`

Заголовки внутри fenced code blocks не считаются разделами. Дополнительные
заголовки уровня 2 и текст до первого раздела отклоняются. Проверка структуры
не гарантирует содержательную точность: готовый файл остаётся черновиком.

Валидный результат записывается атомарно, затем фаза меняется на `analyzed`,
затем отправляется локальное уведомление. Ошибка уведомления не вызывает
повторный анализ. Невалидный результат не создаёт черновик, не переводит фазу
и не делает запись кандидатом на retention. Существующий черновик нельзя
перезаписать невалидным ответом.

## Проверки и ввод в работу

Тесты используют подставные runner/API/часы и временные файлы, без сетевых вызовов:

- конфигурация и аргументы Codex, stdin, таймаут, ephemeral, отдельный файл ответа;
- успех, ненулевой exit code, пустой или отсутствующий ответ;
- правильные разделы, пропуск, дубль, неверный порядок, пустое содержимое,
  заголовки внутри code fence, сообщение об ошибке вместо документа;
- попытки и сроки после повторной загрузки состояния, предел трёх вызовов;
- глобальная блокировка прекращает вызовы для остальных встреч того же тика;
- ручное возобновление, аварийное завершение, повреждённое состояние;
- миграция старого формата, блокировка одновременных процессов;
- отсутствие персональных данных и доступа к записи в отправляемом промпте;
- ошибка уведомления не запускает анализ заново; невалидный ответ не запускает
  retention для этой записи.

После целевых тестов запускаются общий набор тестов tools и сборка сайта.
Затем выполняется синтетический тест Codex с проверкой изоляции и формата.
Один анализ существующей записи выполняется отдельным режимом без скачивания,
удаления облачной записи или отправки сообщений людям. Проверяются результат
и сохранённое состояние; повторный запуск не должен обращаться к модели.
Только после этого восстанавливается часовой LaunchAgent.

Архивируются только чаты, у которых совпадают исходное задание и подтверждённый
источник повторов; рабочий чат и содержательные результаты сохраняются.
После архивирования проверяется состояние Recents. Публикация и push не входят
в эту работу.
