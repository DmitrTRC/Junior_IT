# История Python: версии и изменения языка

> Полная хронология от ABC и рождественских каникул 1989 года до Python 3.14
> (октябрь 2025) и того, что заявлено в 3.15 (октябрь 2026).
> Справочник для разработчика. Актуально на **12 сентября 2026**.

---

## 0. Как устроено версионирование и кто решает

### Имена и цифры

| Термин | Что это |
|---|---|
| **Python** | Имя языка. В честь «Monty Python's Flying Circus», не в честь змеи. Логотип со змеями появился позже и прижился. |
| **CPython** | Эталонная реализация на C. Когда говорят «Python 3.14 вышел» — речь про CPython. |
| **PEP** | Python Enhancement Proposal — документ, через который в язык попадает любое изменение. Аналог TC39-пропозалов у JavaScript, но со сквозной нумерацией с 2000 года. |
| **python.org / PSF** | Python Software Foundation — некоммерческий фонд, владеющий торговой маркой и инфраструктурой. |

### Процесс PEP

| Статус | Смысл |
|---|---|
| Draft | Черновик, обсуждается |
| Accepted | Принят, ждёт реализации |
| Final | Реализован и вошёл в релиз |
| Rejected / Withdrawn | Отклонён или отозван автором |
| Deferred | Отложен до лучших времён |

Ключевые «конституционные» PEP, которые стоит знать по номерам:

- **PEP 1** — что такое PEP и как он живёт.
- **PEP 8** — стиль кода. Самый цитируемый документ экосистемы.
- **PEP 20** — The Zen of Python (`import this`), 19 афоризмов Тима Питерса.
- **PEP 13** — устройство власти после ухода Гвидо (Steering Council).
- **PEP 387** — политика обратной совместимости: депрекация минимум два релиза до удаления.
- **PEP 602** — годовой цикл релизов (с 3.9).

### Каденция и поддержка

С **PEP 602** (2019) релизы выходят **каждый октябрь**. Каждая версия живёт
**5 лет**: примерно 2 года bugfix-релизов, затем только security-патчи.
С 3.13 действует уточнение (PEP 602 rev.): полных bugfix-лет снова два,
но первый год релиз считается «самым свежим стабильным», а прошлогодний —
«рабочей лошадью». Для учебных целей это означает простое правило: **ставить
прошлогодний октябрьский релиз — всегда безопасно**.

## 1. Предыстория: ABC и Амстердам (1980-е)

Гвидо ван Россум работал в CWI (Амстердам) над языком **ABC** — учебным
языком, который должен был заменить BASIC. ABC дал Python почти всё
узнаваемое: отступы вместо скобок, высокоуровневые типы (списки, словари,
строки произвольной длины), интерактивный режим, принцип «язык должен
читаться». Но ABC был закрытой монолитной системой без расширяемости —
и провалился.

Вторая составляющая — ОС **Amoeba**, для которой Гвидо нужен был скриптовый
язык-клей. Третья — Modula-3, откуда пришла система исключений и модулей.

На рождественских каникулах **декабря 1989** Гвидо начал писать интерпретатор
«нового языка, наследника ABC, который понравился бы Unix/C-хакерам».
Название взял с полки — по кассетам Monty Python.

## 2. Ранний период: 0.9 → 1.x (1991–1999)

### 0.9.0 — 20 февраля 1991

Первая публикация — в юзнет-группу `alt.sources`. Уже были: классы
с наследованием, исключения, функции, типы `list`, `dict`, `str`, модули.
То есть Python родился почти узнаваемым — дальше язык не перестраивался,
а наращивался.

### 1.0 — январь 1994

Функциональные инструменты: `lambda`, `map`, `filter`, `reduce` (внесены
сторонним контрибьютором; Гвидо позже признавался, что не любил их).

### 1.4 — 1996 · 1.5.2 — 1999

Именованные аргументы, встроенная поддержка комплексных чисел, зачатки
сокрытия имён (`_name` mangling). **1.5.2** — первая «народная» версия,
которую многие старые книжки считают точкой отсчёта.

### Драма лицензий: 1.6 и CNRI

Гвидо переехал из CWI в CNRI (Вирджиния), потом в BeOpen. Версии 1.6/2.0
выходили под юридически мутными лицензиями; сообщество нервничало. Всё
закончилось хорошо: PSF License, совместимая с GPL, и создание фонда PSF
(2001).

## 3. Эпоха Python 2 (2000–2010)

### 2.0 — 16 октября 2000

- **List comprehensions** — `[x*x for x in xs if x > 0]` (идея из Haskell).
- Полноценный **сборщик мусора циклов** вдобавок к подсчёту ссылок.
- Юникод-строки `u"…"` (отдельным типом — мина, которая рванёт в 3.0).
- Разработка переехала на открытый багтрекер — Python стал по-настоящему
  общественным проектом.

### 2.1 — 2001 · 2.2 — декабрь 2001

2.1: вложенные области видимости (замыкания стали работать как ожидаешь).

**2.2 — самый важный релиз двойки:**

- **Объединение типов и классов** («new-style classes», `object` как база) —
  до этого встроенные типы и пользовательские классы жили в разных мирах.
- **Генераторы** (PEP 255) и протокол **итераторов** — `yield` появился здесь.
- Дескрипторы, `property`, `classmethod`, `staticmethod`, `super()`,
  метаклассы — вся современная объектная машинерия Python родом из 2.2.

### 2.3 — 2003 · 2.4 — 2004 · 2.5 — 2006

- 2.3: `enumerate()`, `sum()`, тип `bool` как отдельный, `sets` в stdlib,
  `logging`, `datetime`.
- 2.4: **декораторы** `@` (PEP 318), генераторные выражения, `sorted()`,
  `set`/`frozenset` встроенными, `decimal`.
- 2.5: **`with`** и контекстные менеджеры (PEP 343), тернарный
  `a if cond else b`, `try/except/finally` в одном блоке, абсолютные импорты
  (PEP 328), `ctypes`, `sqlite3` и `ElementTree` в stdlib.

### 2.6 — 2008 · 2.7 — 3 июля 2010

Обе версии — «мосты» к тройке: в них бэкпортировали синтаксис 3.x, чтобы
код мог работать в обоих мирах. 2.7 получил словарные/множественные
comprehensions, `str.format`, `argparse`, `OrderedDict`, `Counter`.

**2.7 — версия-долгожитель.** Поддержку продлевали дважды; официальная
смерть — **1 января 2020**, почти десять лет жизни. Причина долголетия —
болезненность перехода на тройку (см. ниже).

## 4. Раскол: Python 3000 (2008)

**3.0 — 3 декабря 2008.** Единственный намеренно несовместимый релиз
в истории языка. Гвидо копил список «ошибок дизайна» годами и исправил их
разом:

- `print` — функция, а не оператор.
- Строки: единый юникодный `str`, отдельный `bytes`. Главная и самая
  болезненная правка — но именно она сделала Python языком, где «строка —
  это текст, а не массив байтов».
- `1/2 == 0.5` — честное деление; целочисленное — `//`.
- `range`, `map`, `filter`, `dict.keys()` — ленивые, а не списки.
- Убраны старые классы, `<>`, `cmp`, неявные сравнения разнотипного.

**Переход занял ~10 лет.** Экосистема (NumPy, Django, библиотеки) мигрировала
медленно, сидя на 2.7. Инструменты эпохи: `2to3`, `six`, «straddling code».
Урок, который индустрия выучила: **больших несовместимых версий больше
не будет** — это официальная позиция команды (никакого «Python 4»).

### 3.1 (2009) · 3.2 (2011)

Наведение порядка после раскола: `OrderedDict`, ускорение I/O; в 3.2 —
`concurrent.futures`, стабильный ABI (PEP 384), `argparse`.

## 5. Тройка взрослеет: 3.3–3.4 (2012–2014)

- **3.3**: `yield from` (PEP 380 — фундамент будущего `await`), `venv`
  в stdlib, вернули литерал `u"…"` для облегчения миграции, пространства
  имён-пакеты (PEP 420), `unittest.mock`.
- **3.4**: **`asyncio`** (PEP 3156, пока с `@coroutine`/`yield from`),
  `enum`, `pathlib`, `statistics`, `tracemalloc`, `ensurepip` — pip теперь
  идёт с языком.

## 6. Современный Python складывается: 3.5–3.9 (2015–2020)

### 3.5 — сентябрь 2015

- **`async` / `await`** (PEP 492) — асинхронность становится синтаксисом.
- **Типизация: `typing`** (PEP 484) — аннотации получили смысл; начало
  крупнейшего сюжета последнего десятилетия.
- Оператор `@` для матриц (PEP 465 — реверанс NumPy-миру).
- Распаковка везде: `f(*a, *b)`, `{**d1, **d2}` (PEP 448).

### 3.6 — декабрь 2016

- **f-строки** (PEP 498) — самый любимый синтаксис современного Python.
- Словари стали компактными и **сохраняют порядок вставки** (пока как
  деталь реализации).
- Аннотации переменных (PEP 526), подчёркивания в числах `1_000_000`,
  `secrets`, протокол `__init_subclass__`, асинхронные генераторы.

### 3.7 — июнь 2018

- **`dataclasses`** (PEP 557).
- Порядок словарей — **гарантия языка**.
- `breakpoint()`, отложенные аннотации по `from __future__ import
  annotations` (PEP 563 — сюжет с продолжением), контекстные переменные
  для asyncio (PEP 567).

### 3.8 — октябрь 2019

- **Морж** `:=` (PEP 572) — присваивание в выражении. Дискуссия вокруг
  него стоила Гвидо должности BDFL (см. §11).
- Позиционные параметры `/` (PEP 570), `f"{x=}"` для отладки,
  `functools.cached_property`, `Literal` и `Protocol` в typing.

### 3.9 — октябрь 2020

- `dict | dict` (PEP 584), `str.removeprefix/removesuffix` (PEP 616).
- **Дженерики строчными**: `list[int]` вместо `List[int]` (PEP 585).
- `zoneinfo` — часовые пояса в stdlib (PEP 615).
- Новый **PEG-парсер** (PEP 617) — снял ограничения старой грамматики
  и открыл дорогу `match` и мягким ключевым словам.
- Первая версия годовой каденции (PEP 602).

## 7. Наш диапазон: 3.10–3.13 (2021–2024)

Версии, которые реально стоят на машинах курса (правило курса — «3.10+»).

### 3.10 — октябрь 2021

- **`match` / `case`** — структурное сопоставление (PEP 634–636): не switch,
  а разбор формы данных с привязкой имён.
- `int | str` в аннотациях (PEP 604).
- **Человеческие сообщения об ошибках** — начало большой кампании: точное
  место, подсказки «did you mean». Для обучения детей это подарок — мы
  прямо строим на этом такт про чтение ошибок.
- Скобочные многострочные `with (a() as x, b() as y):`.

### 3.11 — октябрь 2022

- **Скорость: в среднем +25%** — первый плод проекта Faster CPython
  (специализирующий адаптивный интерпретатор, PEP 659).
- **Группы исключений** и `except*` (PEP 654), `add_note()`.
- Точная подсветка места ошибки в трейсбеке (`~~~^~~~`, PEP 657) — вторая
  часть подарка для обучения.
- `tomllib`, `Self` в typing, `asyncio.TaskGroup`.

### 3.12 — октябрь 2023

- **Новый синтаксис дженериков**: `def f[T](x: T) -> T`, `class C[T]:`,
  `type Alias = …` (PEP 695) — типизация без импортов из typing.
- f-строки формально в грамматике (PEP 701): любые кавычки внутри,
  многострочность — ограничения сняты.
- Пер-интерпретаторный GIL на C-уровне (PEP 684) — тихий фундамент
  free-threading-сюжета.
- Выпилен `distutils` (PEP 632); `pathlib.Path.walk()`.

### 3.13 — октябрь 2024

- **Новый REPL**: цвет, многострочное редактирование, F2-история —
  интерактив, который видят дети при `python3`, стал человеческим.
- **Free-threaded сборка (без GIL)** — экспериментально (PEP 703),
  отдельным бинарём `python3.13t`.
- **JIT** — экспериментальный copy-and-patch (PEP 744), по умолчанию
  выключен.
- «Мёртвые батарейки» удалены: 19 старых модулей (`cgi`, `telnetlib`…)
  покинули stdlib (финал PEP 594).
- iOS и Android — официально поддерживаемые платформы (PEP 730/738).

## 8. Текущий стабильный: 3.14 — 7 октября 2025

Число версии совпало с π — команда шутила про это весь цикл.

- **t-строки** (PEP 750): `t"…"` — шаблонные литералы, которые вместо
  готовой строки дают структуру «текст + значения». База для безопасных
  SQL/HTML-шаблонов без инъекций.
- **Аннотации стали ленивыми по умолчанию** (PEP 649/749) — двадцатилетний
  сюжет закрыт: аннотации больше не вычисляются при определении функции,
  `from __future__ import annotations` уходит в историю.
- **Free-threading — официально поддерживаемая опция** (фаза II по
  PEP 779): уже не эксперимент, хоть и не сборка по умолчанию.
- **Субинтерпретаторы из Python** — модуль `concurrent.interpreters`
  (PEP 734): изоляция как у процессов, цена как у потоков.
- Отладчик подключается к живому процессу: `python -m pdb -p PID`
  (PEP 768).
- Подсветка синтаксиса прямо в REPL; `compression.zstd` (PEP 784);
  UUID v6–v8; дальнейший прирост скорости (хвостовые вызовы
  в диспетчеризации интерпретатора на поддерживающих компиляторах).

## 9. Что заявлено в 3.15 (октябрь 2026)

Релиз ожидается в следующем месяце; сейчас в стадии RC. Из принятого:

- **UTF-8 по умолчанию** (PEP 686): файлы открываются в UTF-8 на любой
  платформе — конец эпохи «на Windows прочиталось в cp1251».
- Продолжение free-threading (производительность однопоточного кода
  в свободнопоточной сборке) и JIT-раскачка.
- Точный состав фич фиксируется к RC — таблицу стоит обновить после
  релиза.

## 10. Сквозные сюжеты

### Скорость: Faster CPython → JIT

Десятилетиями CPython был «медленным, и ладно» — скорость разработчика
важнее скорости программы. С 3.11 позиция изменилась: специализирующий
интерпретатор (+25%), с 3.13 — экспериментальный JIT, в 3.14+ — его
постепенное включение в строй. Итог для нас: **школьные задачи летают
на любой версии**, но аргумент «Python медленный» устаревает на глазах.

### GIL и free-threading

GIL — глобальная блокировка, из-за которой потоки CPython не исполняют
байткод параллельно. Сага о его удалении шла с 1990-х (Gilectomy и др.)
и завершается на наших глазах: PEP 703 (принят 2023) → экспериментальная
сборка в 3.13 → официальная поддержка в 3.14 → цель — стать умолчанием
(фаза III, срок не назначен). Для курса: рассказывая про потоки, честно
говорим «правило меняется прямо сейчас».

### Типизация

1991: типов в сигнатурах нет вовсе → 3.0: аннотации без смысла → 3.5:
`typing` → 3.9: `list[int]` → 3.10: `X | Y` → 3.12: `def f[T](…)` →
3.14: ленивые аннотации. Питон остался динамическим — типы это
инструменты проверки (mypy, pyright), а не рантайм. Наш курс держит
типизацию за кадром до продвинутых модулей.

### Упаковка и инструменты — кратко

`distutils` (2000) → `setuptools`+`easy_install` → **`pip`** (2008,
в комплекте с 3.4) → колёса `wheel` (PEP 427) → `pyproject.toml`
(PEP 517/518) → `venv` в языке → современная волна на Rust: `uv`, `ruff`
(2023+) — порядок наводится, но истории «десяти способов поставить пакет»
хватит на отдельный документ.

### Реализации, кроме CPython

| Реализация | Зачем |
|---|---|
| **PyPy** | JIT-реализация, в разы быстрее на долгих вычислениях |
| **MicroPython** | Микроконтроллеры (та же ESP32 на столе у радиолюбителя) |
| **Pyodide** | CPython в браузере через WebAssembly — наш кандидат для тренажёра, если появится группа без «своих» машин |
| Jython / IronPython | JVM / .NET, застряли на старых версиях |
| RustPython | Реализация на Rust, скорее исследовательская |

## 11. Власть: от BDFL к Steering Council

До 2018 Гвидо был **BDFL** — «великодушным пожизненным диктатором».
В июле 2018, устав от токсичности споров вокруг моржа (PEP 572), он
сложил полномочия одним письмом: «Now that PEP 572 is done, I don't ever
want to have to fight so hard for a PEP…».

Сообщество выбрало модель управления голосованием (PEP 8016 → PEP 13):
**Steering Council** из пяти человек, переизбираемый на каждый релизный
цикл. Гвидо входил в первый состав, сейчас — на пенсии (после паузы
в Microsoft, где толкал Faster CPython). Модель работает: моржа пережили,
free-threading принят без гражданской войны.

## 13. Что из этого видит наш курс

- **Правило курса — «3.10 или новее»**: нам нужны человеческие сообщения
  об ошибках (3.10/3.11) — на них построен такт про чтение трейсбека.
  Всё остальное в программе работает и на 3.10, и на 3.14.
- На маках курса ставится **свежий стабильный** (сейчас 3.14) — заранее,
  до занятия, по `provisioning/`.
- Тексты ошибок отличаются между версиями (например, у старых версий
  `EOL while scanning string literal` вместо `unterminated string
  literal`) — в материалах это оговорено.
- `match`, моржа, типизацию и асинхронность курс сознательно держит
  за горизонтом первых модулей: сначала переменные, ветвления и циклы —
  ровно та часть языка, что не менялась с девяностых. Это, кстати,
  главный вывод всей хронологии: **ядро, которое учит ребёнок, стабильно
  тридцать лет** — меняется обвязка вокруг.
