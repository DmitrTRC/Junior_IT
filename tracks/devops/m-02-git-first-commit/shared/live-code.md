# Git — история собственного файла

Все работают в отдельной учебной папке `git-lab`, не в чужом репозитории.
Из Python-блока скопируй туда свой `dialogue.py`, затем открой терминал
именно в `git-lab`. Команды ниже выполняются по одной.

## 1. Папка становится репозиторием

```sh
git init
git status
```

`git status` покажет `dialogue.py` как ещё не отслеживаемый файл.
Папка `.git` — служебная история. Её не редактируем. Название ветки
`main` или `master` сейчас не важно.

## 2. Подготовить и сохранить

```sh
git add dialogue.py
git status
git commit -m "Add dialogue"
git log --oneline
```

`add` выбирает файл для версии, `commit` сохраняет её, `log` показывает
историю. Обычное сохранение в редакторе не создаёт коммит.

Если Git просит подпись автора, только в этой учебной папке:

```sh
git config user.name "Learner"
git config user.email "learner@example.invalid"
```

Это вымышленная локальная учебная подпись, не регистрация и не пароль
GitHub. Для настоящего репозитория позже настроим выбранную подпись
отдельно. Повтори неудавшийся `git commit`.

## 3. Вторая версия

Измени приветствие в своём файле, сохрани, запусти и убедись, что новый
текст появился. Потом:

```sh
git status
git add dialogue.py
git commit -m "Change greeting"
git log --oneline
```

У каждого две версии, самая новая — первой. Файл сохранили до `add`.
Если изменили после `add`, выполни `git add dialogue.py` ещё раз.

## 4. Открыть GitHub

Git хранит историю на компьютере. GitHub — сайт для удалённых
репозиториев. Локальный `commit` сам ничего туда не отправляет.
При готовом доступе сохрани свой код через веб-интерфейс в
`hw/python-02-input/dialogue.py` закрытого репозитория, который даёт
преподаватель. Открой файл и его History, найди свою запись.

Это отдельное сохранение через сайт: два локальных коммита автоматически
не перенеслись. Позже клонируем репозиторий GitHub и научимся отправлять изменения
командой `push`. Сегодня не вводим одновременно SSH, токены, ветки и PR.
