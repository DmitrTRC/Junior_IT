# Hello, World: чем платим за высокий уровень

Один и тот же результат — строчка `Hello, World!` в stdout — семью разными
способами. Сравниваем **размер файла**, **пиковую резидентную память (RSS)**
и **время старта процесса**.

Замерено на: `aarch64`, Linux 6.8, gcc 11, Python 3.10, Node 22.

## Результаты

| Вариант | Файл | Пик RSS | Старт |
|---|---:|---:|---:|
| C, без libc (только syscall) | **928 B** | **128 KB** | 0.61 ms |
| C, `-Os -s`, динамическая линковка | 6.0 KB | 896 KB | 0.77 ms |
| C, `-O0` — как обычно учат | 8.7 KB | 896 KB | 0.70 ms |
| C, статический (`-static`) | 536 KB | 384 KB | 1.79 ms |
| Python, исходник | 207 B | 7.9 MB | 11.0 ms |
| Python → PyInstaller (один файл) | **5.7 MB** | **12 MB** | 124 ms |
| Node.js, исходник | 120 B | 41 MB | 18.0 ms |

Ключевая цифра для доски: **928 байт против 5.7 мегабайт** — в 6100 раз.
По памяти — 128 КБ против 12 МБ, почти в 100 раз. Работа одна и та же.

## Что в этих файлах

- `hello.c` — классика через `printf`.
- `hello_bare.c` — то же самое без стандартной библиотеки: точка входа `_start`,
  вывод и выход — сырые системные вызовы через `svc #0` (на x86_64 — `syscall`).
- `hello.py` — Python.
- `hello.js` — Node.js, для сравнения рантаймов.
- `build.sh` — собирает все варианты в `build/`.
- `measure.sh` — печатает таблицу выше на любой машине.

```bash
./build.sh && ./measure.sh
```

## Как читать эти цифры

**Размер файла ≠ размер программы.** Динамический C-бинарник весит 6 КБ, но
тянет за собой `libc.so.6` (1.6 МБ на диске). Просто эта libc одна на всю
систему и уже в памяти — за неё заплатил кто-то другой. Статический бинарник
честно кладёт нужные куски libc внутрь себя: 536 КБ на диске, зато ноль
зависимостей — скопировал и запустил.

**Статический RSS меньше динамического** (384 КБ против 896 КБ) — на первый
взгляд парадокс. На деле динамический вариант поднимает `ld-linux.so`, тот
маппит libc, разбирает таблицы релокаций, отрабатывает PLT/GOT. Статическому
всё это не нужно: ядро отобразило один сегмент и передало управление.

**Python-исходник — 207 байт, но 7.9 МБ RSS.** Файл крошечный, потому что это
не программа, а входные данные для программы. Настоящий исполняемый файл здесь
— интерпретатор `/usr/bin/python3` плюс ~42 МБ стандартной библиотеки на диске.
Он парсит исходник, строит AST, компилирует в байт-код и только потом исполняет.

**PyInstaller — это архив с интерпретатором внутри.** 5.7 МБ — упакованный
CPython, `libpython`, часть stdlib и наш скрипт. При запуске он распаковывает
всё это во временную папку и запускает оттуда — отсюда 124 мс старта, в 200 раз
медленнее C. Это не «скомпилированный Python»: байт-код как был, так и остался,
просто интерпретатор едет в том же чемодане.

**Node — 41 МБ RSS на одну строчку.** V8 разворачивает кучу, JIT, GC,
изоляты, event loop. Всё это окупается на большой программе и выглядит
абсурдно на маленькой.

## Вся программа в 12 инструкциях

`hello_bare` после `strip` — 928 байт файла, из них **135 байт кода**:

```asm
40010c:  adrp x1, 0x400000      ; адрес строки, старшие биты
400110:  mov  x8, #64           ; номер сисколла write (aarch64)
400114:  mov  x0, #1            ; fd = 1, stdout
400118:  add  x1, x1, #0x138    ; адрес строки, младшие биты
40011c:  mov  x2, #14           ; длина
400120:  svc  #0                ; -> ядро
400124:  mov  x8, #93           ; номер сисколла exit
400128:  mov  x0, #0            ; код возврата
40012c:  mov  x1, #0
400130:  mov  x2, #0
400134:  svc  #0                ; -> ядро, обратно не возвращаемся
```

Остальные 793 байта файла — это ELF-заголовок, три program header'а, секция
`.note.gnu.build-id` и выравнивание. То есть **больше половины «программы» —
это конверт, а не письмо**. Меньше на Linux уже не сделать, не занимаясь
ручной сборкой ELF (есть известные экземпляры на 45 байт, но это уже спорт).

## О чём этот пример на самом деле

Не о том, что C хороший, а Python плохой. О том, что **у уровня абстракции
есть цена, и её полезно знать в цифрах**.

- Пишете прошивку для микроконтроллера с 64 КБ RAM — 12 МБ рантайма вам
  недоступны физически.
- Пишете CLI-утилиту, которая дёргается из скрипта тысячу раз — 124 мс старта
  превращаются в две минуты чистого ожидания.
- Пишете разовый скрипт обработки CSV — 12 МБ и 100 мс не стоят даже упоминания,
  а сэкономленный час вашего времени стоит.

Правильный вопрос не «какой язык быстрее», а «что здесь дефицитный ресурс:
память, старт, время исполнения — или время разработчика».

## Повторить на своей машине

```bash
git clone <этот репозиторий>
cd hello-world-sizes
pip3 install pyinstaller     # только для последнего варианта
./build.sh
./measure.sh
```

Скрипты рассчитаны на Linux (GNU `time`, `numfmt`, `stat -c`). На macOS проще
всего запустить в контейнере или подставить BSD-шные аналоги; `hello_bare.c`
там не соберётся вовсе — Apple не поддерживает прямые сисколлы в обход libSystem,
и это само по себе хорошая тема для отдельного разговора.
