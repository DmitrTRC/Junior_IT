# Две версии своей программы

После занятия 14.10. **10–15 минут**. Нужен твой работающий `dialogue.py`.

## Что сделать

Если две версии уже готовы, выбери ещё одно своё изменение: добавь вопрос
или измени ответ программы. Повтори запуск и сохрани новый коммит.
Не нужно начинать историю заново.

1. Открой отдельную учебную папку `git-lab`, с которой работал на занятии.
   Если начинаешь с нуля, создай её вне других репозиториев и скопируй туда свой диалог.
2. Запусти программу. Она должна спрашивать ник и жанр и выводить твои ответы.
3. Выполни `git log --oneline`. Если истории ещё нет, выполни `git init`,
   `git add dialogue.py`, `git commit -m "Add dialogue"`.
4. Измени приветствие на своё. Сохрани файл, запусти его снова и убедись,
   что новый текст появился. Выполни `git add dialogue.py` и
   `git commit -m "Improve greeting"`.
5. Посмотри `git log --oneline`: найди версию до и после изменения.
   Коммитов может быть больше двух, если ты продолжил историю с занятия.
6. Создай `history.txt`: вставь две нужные строки из `git log --oneline`,
   подпиши, что изменилось, и одним предложением объясни отличие Save от commit.

Используй вымышленный ник. Запусти диалог с двумя разными наборами ответов.
Подсказки — [шпаргалка Git](../../tracks/devops/m-02-git-first-commit/student/cheatsheet.html).

## Если Git пока не работает

Сохрани варианты как `dialogue-v1.py` и `dialogue-v2.py` и опиши изменение
в `history.txt`. Это подготовка к истории Git; коммиты сделаем после настройки.
Не устанавливай программы и не создавай аккаунт наугад.

→ Commit changes. Такая загрузка сохраняет файлы, но не переносит локальную историю.

срок загрузки согласуем после настройки. Скриншоты и архив `.git` не нужны.
