Сайт — статический HTML/CSS/JS, без прикладного сервера.
`tools/build_site.sh` собирает белый список файлов, затем карту,
программу и страницы домашек/словариков. `teacher/`, `live-code.md`,
`meta/`, `students/`, `recordings/`, `docs/superpowers/` на сайт
не копируются. Это не делает отслеживаемые файлы приватными: репозиторий
сам публичный. В домашках публикуются условие и файлы верхнего уровня,
но не `task.md` и не каталог `tests/`.

GitHub Actions публикует сайт при push в `main`. Push — только по прямой
команде Димаса. Генерируемые `course-map.json`, `program.json`, `_site/`
не редактировать вручную. Поле `completed: []` в новом плане не даёт
автоматически засчитать плейлист после даты занятия.

## Подготовка и сдача

Сначала условие на сайте; в Telegram — копия того же текста, MAX —
ручной дубль при необходимости. Решения — файлами в личном репозитории
GitHub, путь `hw/<id>/`. Не подменять код скриншотом запуска или версии
Python. При отсутствии доступа сохранить локально и согласовать настройку.

Первая ступень — сохранение в `main`, далее ветки/PR/CI по готовности
ученика. Опрос GitHub фиксирует поступление работы; это не равнозначно
правильному решению. Старая `meta/git-strategy.md` описывает публичные
репозитории, а более новая схема comms — закрытые репозитории преподавателя
с доступом ученика. Для нового подключения использовать последнюю схему.

Планы 30.09 и локальный разбор подтверждают практику hello.py/broken.py.
Тренажёр §1.1 и переменные в группе не состоялись. Отдельные занятия
были: не приравнивать отсутствие общей записи к отсутствию практики.

## Открытые вопросы

- **Подключение учеников:** подтвердить доступ к GitHub до использования
  нового канала сдачи; развёртывание comms/courier пока не подтверждено.
- **Zoom и NAS:** `_find_file()` в `tools/zoom_pipeline/phases.py`
  выбирает первый сегмент; объединения записей нет. Недоступность NAS
  останавливает цепочку до распознавания. Требуется проверить доступ.
- **Обезличивание:** Zoom обрабатывает transcript, но метаданные встречи,
  session YAML и доступ к записи идут в prompt без этой обработки.
  `tools/comms/apply.py` передаёт модели имя и отчёт журнала напрямую.
  Учесть эту границу при миграции провайдера. Исторические `session.yml`
  также содержат личные имена/посещаемость в публичном репозитории;
  исключение из Pages не скрывает их в Git.
- **Программа года:** `meta/program.yml` ставит CS-02 в ноябрь, а
  требуемый им CS-01 — в декабрь; порядок расходится с `requires`.
- **Банк вопросов:** `textbook/quizzes/REVIEW-07-1.md` остаётся черновиком
  под сверку с бумажным учебником; валидатор проверяет структуру, не вычитку.
- **Документы:** README обещает git со второго занятия и CI с конца
  сентября; атлас `textbook/atlas-07.md` хранит старые даты.
  `meta/project-instructions.md` содержит прежние формат, каналы сдачи
  и число модулей. Для текущей работы использовать `AGENTS.md` и план 04.10.
  `.claude/commands/new-module.md` ещё ошибочно исключает домашки из сайта.
- **Предпросмотр:** `.zellij/cockpit.yml` запускает сервер из корня,
  без `--directory _site`; генерируемые страницы при этом недоступны.
- **CI:** workflow деплоя запускает банк и JS-тесты, но не Python suites
  и не валидатор модулей. Локальный зелёный прогон шире CI.
- **Provisioning:** установка Homebrew в `setup-mac.sh` и команда установки
  uv в `provisioning/courier/setup.md` используют curl без таймаута.
  Подстановка загрузчика Homebrew выполняется и при DRY_RUN, если brew
  отсутствует; такой запуск не считать безопасной симуляцией.

Это наблюдения для отдельных задач, а не выполненные исправления.
