# Git-стратегия для учеников

Зафиксирована 16.09.2026. Вытекает из спеки реструктуризации
(`docs/superpowers/specs/2026-09-09-course-restructure-design.md`):
репозиторий ученика публичный, домашка = ветка + PR + CI,
git вводится тремя ступенями.

## Модель

Один ученик — один репозиторий. Одна домашка — одна ветка — один PR.

- `main` — витрина: только смёрженные, зелёные домашки. Merge = «сдано».
- Рабочие ветки `hw/<id-домашки>` (`hw/python-01-first-run`,
  `hw/devops-01-terminal`). Имя ветки печатается в стартере домашки —
  ребёнок копирует, а не придумывает.
- PR в свой же `main`: зелёная галка CI — «правильно», ревью Димаса —
  «хорошо». После мерджа ветка удаляется кнопкой.
- Конфликтов нет по построению: каждая домашка в своей папке.

## Три ступени

1. **Старт** — коммиты прямо в `main`. Git = «сохранить и показать».
   Слово «ветка» не звучит.
2. **Со 2–3-й домашки** — ветка + PR по шаблону + merge после зелёного
   CI. Протект `main` («только через PR») включается ровно в этот
   момент — раньше он только мешает.
3. **Позже** — ревью-комментарии и доработка в той же ветке. Rebase не
   даём вовсе: merge-коммитов достаточно, история ребёнка честная,
   а не красивая.

Ступень назначается на ученика, не на группу: Неля может уйти на
ступень 2 раньше новеньких.

## Запреты на всех ступенях

- force-push;
- работа в чужом репозитории;
- ветки «про запас» без домашки.

Junior_IT дети не трогают: находки в errata коммитит Димас с их
авторством — это ачивка «Поправка к учебнику».
