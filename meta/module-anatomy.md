# Анатомия модуля Junior_IT

Заменяет `meta/lesson-anatomy.md`. Канон для `meta/module-template/`, команды
`/new-module` и агента `brand-guardian`. Единица библиотеки — **модуль**, не
урок: занятие собирает модули из разных треков в плейлист.

## Файлы модуля

Папка `tracks/TRACK/m-NN-slug/`, эталон — `meta/module-template/`:

| Файл | Роль | Что это |
|---|---|---|
| `module.yml` | манифест | метаданные модуля: id, трек, длительность, термины, ссылки |
| `shared/slides.html` | shared | слайды для показа на занятии, переключение `←` / `→` |
| `shared/live-code.md` | shared | живой код: шаги, которые набираются на экране при ученице |
| `student/cheatsheet.html` | student | шпаргалка — самодостаточный HTML, отправляется в чат в конце занятия |
| `student/glossary.md` | student | словарик модуля, три колонки (см. ниже) |
| `teacher/scenario.md` | teacher | сценарий с таймингом по минутам и чек-листом готовности |

`shared/` — то, что видно на экране во время занятия. `student/` — то, что
уходит ребёнку после. `teacher/` — материалы преподавателя: сценарий с
таймингом, разбор; на сайт не публикуются.

## Домашка

Домашка не входит в папку `tracks/TRACK/m-NN-slug/` — на неё указывает поле
`homework` в `module.yml`. Две формы, обе легитимны, не смешивать:

- **Текущая конвенция (новые модули — `book`, `devops`, `python`):**
  `homework/TRACK-NN-slug/task.md` в корне репозитория. Папка `homework/`
  исключена из сборки сайта (`tools/build_site.sh`) — условие видит только
  преподаватель, ученице передаётся отдельно (текст/скриншот/вложение в
  мессенджере).
- **Наследие (11 перенесённых модулей `cs` и `web`):** `student/homework.html`
  внутри самого модуля — публикуемый самодостаточный HTML со стартером и
  условием сразу на странице. Не переносить на новые модули; существующие
  не переписывать под текущую конвенцию без отдельной задачи.

`/new-module` создаёт домашку по текущей конвенции (`homework/`), не по
наследию.

## `README.md` модуля (наследие)

Те же 11 перенесённых модулей держат `README.md` в корне модуля — вводный
конспект урока (тема, что ребёнок умеет к концу, таблица файлов), появился
до разделения на роли `shared/student/teacher`. Новые модули его не заводят:
вводную роль закрывают `module.yml` и `teacher/scenario.md`.

## Схема `module.yml`

| Поле | Тип | Обязательное | Допустимые значения | Что это |
|---|---|---|---|---|
| `id` | строка | да | `TRACK/m-NN-slug`, совпадает с путём папки | связывает манифест с местом в дереве |
| `title` | строка | да | `"Тема (topic in English)"` | заголовок в библиотеке и на титульном слайде |
| `track` | строка | да | `book`, `python`, `pascal`, `devops`, `cs`, `web` | к какому треку принадлежит модуль |
| `level` | строка | да | `core`, `deep`, `optional` | `core` — основной плейлист, `deep` — для желающих глубже, `optional` — вне графика |
| `minutes` | целое > 0 | да | напр. `25` | сколько минут модуль занимает на занятии |
| `textbook` | список строк | нет, по умолчанию `[]` | `"7:1.3"`, `"8:5.4"` — класс:параграф.пункт | какие параграфы учебника закрывает |
| `requires` | список id | нет, по умолчанию `[]` | существующие `id` модулей в `tracks/` | что должно быть пройдено раньше |
| `terms` | список объектов | нет, по умолчанию `[]` | `{ru, en}`, опционально `note` | источник словарика и двуязычных подписей в шпаргалке |
| `quiz` | строка (путь) | нет | существующий путь, обычно `textbook/quizzes/NN-P.P.json` | тест по параграфу, который закрывает модуль |
| `homework` | строка (путь) | нет | существующий путь `homework/TRACK-NN-slug` | домашка-стартер модуля |

Валидатор (`tools/validate_modules.py`) проверяет обязательные поля и допустимые
значения, наличие всех трёх папок ролей, совпадение `id` с путём, и что
`requires`, `quiz`, `homework` указывают на существующее.

### Нумерация

Номер в `m-NN-slug` отражает **порядок создания модуля внутри трека**, не
порядок прохождения. Порядок задаёт плейлист занятия (`playground/<дата>/session.yml`) —
модуль с бо́льшим номером может быть взят раньше модуля с меньшим.

## Двуязычные термины

Каждый термин учебника сопровождается принятым в индустрии английским словом:
«Ветвление (branching)», «Исполнитель (executor)», «ИЛИ (OR)». Это методическая
цель курса, а не украшение. Поле `terms` в `module.yml` — источник истины: из
него собирается `student/glossary.md` и подписи термина на шпаргалке и слайдах.

Формат `student/glossary.md` — таблица из трёх колонок:

| Учебник (рус) | В проде (eng) | Что это одной строкой |
|---|---|---|
| термин | term | объяснение без зубрёжки |

## Цвета треков

Источник истины — `meta/brand-tokens.css`. Каждый трек — пара «тёмный фон
материалов / печать шпаргалки»:

| Трек | Токен | Тёмный фон | Печать |
|---|---|---|---|
| `book` | `--track-book` | `#7aa2ff` | `#2b4fa8` |
| `python` | `--track-py` | `#00ffc8` | `#00806a` |
| `pascal` | `--track-pas` | `#ff5722` | `#b3350f` |
| `devops` | `--track-ops` | `#00e676` | `#00803d` |
| `cs` | `--track-cs` | `#ff0096` | `#a8005f` |
| `web` | `--track-web` | `#8892b0` | `#4a5568` |

В `module.yml` цвета не хранятся — только `track`. В `student/cheatsheet.html` и
`shared/slides.html` пара подставляется в свои локальные `--track` / `--track-ink`
(см. `meta/module-template/`). Чип трека — моноширинный (`JetBrains Mono` 700),
текст — короткий код токена в верхнем регистре (`PY`, `PAS`, `OPS`, `CS`, `WEB`,
`BOOK`), фон — `--track`, цвет текста — `--bg`; при печати фон меняется на
`--track-ink`, цвет текста — белый.

## Отступления блока `cs`

Модули трека `cs` («Компьютер изнутри») сохраняют два отступления от анатомии:

- `shared/live-code.md` — не живой код, а **живая схема**: режиссура сборки
  схемы по слайдам, кода нет.
- Одна интерактивная демка на модуль вместо трёх эстетик (геймер/спорт/арт).

## Проверка

```
cd tools && .venv/bin/python validate_modules.py ..
```

Зелёный прогон — `модулей с ошибками: 0`.

## Пример: `python/m-01-first-run`

Реальный модуль трека `python`, уровень `core`, 25 минут, параграф 8 класса.

```yaml
id: python/m-01-first-run
title: "Первый запуск Python (first run)"
track: python
level: core
minutes: 25
textbook: ["8:5.1"]
requires: [devops/m-01-terminal-first-steps]
terms:
  - {ru: интерпретатор, en: interpreter}
  - {ru: скрипт, en: script}
  - {ru: вывод, en: output}
homework: homework/python-01-first-run
```
